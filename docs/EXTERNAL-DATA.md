# 外部参考データ運用

外部参考情報は、サイト利用者本人の直接投稿を補う資料です。SNSや口コミには選択バイアスがあるため、全国・店舗統計、景品割合、ランキング、店舗評価、不正判定には使用しません。

## 採用基準

- 採用: 店舗名が確認でき、結果について具体的な情報がある
- 強く採用: 店舗名、日付、景品総数、カテゴリ内訳まで確認できる
- 参考: 店舗名とフィギュアの有無など、一部のみ確認できる
- 原則非表示: 店舗不明で「フィギュアが出なかった」などの言及だけ

店舗不明情報は `storeId: null` で内部保存できますが、店舗詳細には表示されません。似た店舗名を推定で結び付けず、公式店舗マスタと照合します。

## 確認レベル

- `evidenceQuality: A`: 店舗・日付・具体的な個数など複数項目を確認
- `evidenceQuality: B`: 店舗は確認できるが、日付や総数など一部が不明
- `evidenceQuality: C`: 店舗または数値に曖昧さが残る。初期運用では原則非表示を検討
- `resultPrecision: complete`: 景品総数と全カテゴリの正確な内訳が一致
- `resultPrecision: partial`: 一部の数値だけ確認
- `resultPrecision: mention_only`: 数値として扱えない言及のみ

`0` は0個だったことを確認した値です。不明は必ず `null` と `quantityKind: "unknown"` にし、0で代用しません。「以上」は確認できた最小数を入れ、`quantityKind: "at_least"` にします。

## 登録ルール

1. `seed/external-reports.json` を編集する
2. 店舗・キャンペーン・カテゴリ・個別景品のIDを既存マスタと照合する
3. 元ページを確認できる場合は `externalUrl` を保存する。未確認なら `null`
4. `pnpm run seed:external` で検証・SQL生成・ローカル投入する
5. 本番テスト後、生成SQLをWranglerでリモートD1へ投入する

カテゴリが判別できないキャラクター名、挑戦回数からの当たり数、利用金額からの景品数などは推測しません。投稿本文の長文、画像、投稿者名、ユーザーID、プロフィールは保存しません。`noteInternal` は判断根拠の短い要約だけにします。

## 非表示

誤情報、店舗取り違え、リンク切れ、元投稿削除、本人からの申し出があった場合は対象IDの `status` を `hidden` にして再投入します。物理削除は原則行いません。店舗詳細APIは `status = 'active'` の行だけを返します。
